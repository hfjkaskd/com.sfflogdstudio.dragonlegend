# Payment controls and account display

RecoveredCashOutPaymentHeader is authored into CashOutWindow. Four original
standard payment Buttons and AccountBtn are bound by code. The caller binds the
existing player/rules and initializes the nested list before payment interaction.
This component does not open the whole window or fabricate account/payout results.

Native evidence:
- CheckAccount 23a7820 / predicate23aa6b4: cash mode stores supplied type, uses
  first PlayerAccount entry whose type matches, displays emailName (+0x18), not
  accountName (+0x10). Null text passes through TMP_InputField's normal setter.
- Absent cash account: prefix `Please enter your ` + provider + ` account here.`.
  Relocated table4bbd240/248/250 points to script strings Paypal, CashApp, CoinBase.
  Types outside1..3 use Zelle (GOT4f1cf08), including unsupported values.
- Gift mode does not change stored payment type. No GiftAccount displays
  `Please enter your account here.`; an existing record displays address (+0x18),
  with null address converted to empty string. It does not display recipient name.
- Payment refresh23a7720 reparents the same payment frame to window then selected
  layout child using SetParent(false), refreshes account, and initializes bottom
  at saved initial selection. The previously selected card frame remains where
  the card click put it. The existing list handles card type refresh.
- CheckLayOut23a9858/OnInit23a6de4 compare config type with `default` (GOT4f1bf98).
  Payment layout requires that exact type and cash mode. This is not an ISO-country
  comparison and does not establish complete country/AB routing.
- AccountBtn branch23aa3ac..23aa48c requests UIAccountView with payment type in cash
  mode or the gift-account window otherwise, then calls CheckAccount immediately.
  Corresponding typed request events are provided; child-window subscribers are
  still to be connected. No account is saved or generated by this component.
