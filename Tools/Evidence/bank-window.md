# Bank window and core end-flow integration

The production CoreRoundFlow prefab now owns an authored BankWindow. BankReady marks a pending event; normal core settlement (after any Free sequence) opens Bank and waits until its close callback clears that event. Only then does the existing ExtraWild guide / spin unlock / save continuation run. Review and cashout branches, the main Bank progress display, broader audio dispatch and full country routing still require further work; this is not proof of complete lifecycle equivalence.

## Window implementation

- `BuildBankWindow.Save` imports the actual UIBankView prefab hierarchy and remaps official Image, Button, legacy Text, TMP and GraphicRaycaster components. Static layouts, fonts, images, materials and original button animation are retained. Grand/Major/Minior use the existing recovered small jackpot icon rigs and original window labels. BankItem subtrees have identical child RectTransform values in all three original instances; only root X differs (-360,0,360). Their authored instances retain each original root transform.
- The dragon, ball and glow rigs use the existing official Unity implementation. Title UIShiny source values are factor .75020033, width .25, rotation 135, softness/brightness/gloss 1, duration 2, loop enabled; the factor is serialized explicitly. The window follows the recovered popup canvas/background/scale transition conventions. All listeners are bound in code to standard Buttons.
- OnBeforeShow 2391768: play `jump` (GOT 4f1d000), store the close Action, SetBankCount(0), initialize jackpots, clear selected/isContinue and set buttons to zero scale, initialize balls as types [2,1,0]. Jackpot initialization uses the existing ConfigManager.GetJackPot and JackPot implementation, including its player reward fields.
- OnAfterShow 2391c3c: random finger selection first, then each of the three floating height/duration pairs. The finger is reused. Continue finger targets Btn.GetChild(1), the actual OpenBtn.
- Selection, continue/leave ads, item reveal and flight completion use the implementations documented in bank-selection, bank-item, bank-continuation, bank-open and bank-float. Core connects FlyRequested to the real existing cash flight presenter with the Bank transform as the top window and Reward as source. The presenter performs the existing reward credit and only then calls the selection continuation.
- OnAfterHide 2392ab0: deactivate, hide finger, invoke the stored close callback, then stop/reset floating items. GM teardown cancels item and selection continuations and the core wait.

## Core integration

Main.BankPop 23bc778 sets Main+219 and refreshes progress; it does not open immediately. The new BankReady subscription preserves deferred opening. CheckBaseEnd 23c56f0 waits for Free completion before the Bank branch; native close callback 23c2f14 clears +219 and calls InitBank. The recovered controller uses its existing Update runner wait so the core continuation resumes after the close event. The corresponding main progress refresh remains pending.

The core wait currently continues into the already recovered ExtraWild/unlock/save path. Native intervening review/cashout branches are not silently considered implemented.
