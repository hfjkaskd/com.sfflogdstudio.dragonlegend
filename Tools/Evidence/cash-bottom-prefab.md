# CashOutBottom prefab and local runtime

Source: current extracted UICashOutView prefab, subtree RectTransform
224592460329389196 (`Bottom`). `BuildCashOutBottom.Save` retains its Image,
Layout, Line1/2/4/3, checkmarks and CtnBtn hierarchy. Original custom behaviour
is replaced by RecoveredCashOutBottom. All remaining components use official
Unity UI/TMP scripts. Standard Button uses code binding with no persistent event.

Original tx_bg02 border (36,8,38,40) is retained. Five extracted sprites are
imported as single, uncompressed sprites. Original msyhbd SDF font and material
already recovered for CashOutItem are referenced, with no font substitution.
Authoring requires those existing font assets; missing GUIDs fail authoring.

Runtime references:
- InitUI 23a0eb8: initializes local model conditions, row visibility, count text,
  independent task/wait checks, initial remaining-time label and countdown.
- RefreshGoldTime 23a09fc: updates remainingTime and label only; positive-time
  refresh uses native `{0:D2}:{1:D2}:{2:D2}` with minutes, seconds, hours argument
  order. Does not recompute completion flags/checkmarks. Expired refresh likewise
  updates text only and does not cancel an old countdown.
- TimeShow 23a0d34 / callback 23a24e8: negative ignores, nonnegative cancels prior,
  positive schedules one-second scaled updates; callback decrements before
  assigning remainingTime and formatting. Zero dispatches refresh, without setting
  completion flags itself. Inactive owner still receives updates. Destroy cancels.
  The official shared update loop uses constant storage rather than creating one
  interval/callback pair per second as the original DOTween Sequence did.
- Click 23a2034 / state machine 23a3724: sound click, fresh first-record lookup,
  live balance check for unrecorded tier, cached task then cached wait gates for
  recorded tier, step6 task-tip gate, otherwise captured-record next-step request.

Window integration events are explicit: AccountRequested(type,id),
MissingCashRequested(formatted body), TipRequested(text),
TaskContinuationRequested(record,nextStep), RefreshRequested and SoundRequested.
No event is auto-approved or treated as payout success. The caller must connect
the actual windows and continuation; this standalone panel does not submit SDK
orders, debit cash, or advance a task merely because the button was clicked.
Step1000 order-dependent presentation remains outside the local implementation.
